# What People Use vidsmith For

## Documentation nobody reads
[visual: person scrolling through a long document on a laptop]
The README you spent a week on gets skimmed in nine seconds. Paste the same words into a script file and vidsmith reads them out loud over footage, and the parts people always miss get watched instead.

## Course and tutorial episodes
[visual: student watching an online lesson at a desk]
A course is thirty short lessons that all have to look the same. The theme, the voice and the caption style live in one config file, so episode thirty matches episode one without anyone remembering how episode one was made.

## Release notes and changelogs
[diagram: a written changelog turning into a short video]
Every release ships a list of changes that reads like a receipt. The same list, narrated over sixty seconds, is something a customer will actually finish before deciding whether to upgrade.

## Shorts from work you already did
[visual: person holding a phone recording a vertical video]
One script builds both shapes. Ask for sixteen by nine for the long cut and nine by sixteen for the vertical one, and the captions reflow to the narrower frame instead of running off the side of it.

## Internal training that goes stale
[visual: team in a meeting room watching a screen]
Onboarding decks rot the moment the process changes. When the video is a text file in the repository, updating it is a pull request, and the new version renders the same way the old one did.

## Anything you would rather not film
[visual: empty home office with a microphone on the desk]
There is no camera, no microphone and nobody on screen. That is the whole appeal for a lot of people, and it is why the output has to be exact rather than roughly right.

## Where to start
[visual: hands typing on a keyboard in a bright room]
Clone it, write four scenes, and run the build. The first one takes about a minute and costs nothing.
